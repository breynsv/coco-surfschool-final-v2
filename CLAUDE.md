# Coco Surf School — working agreement

Static multilingual site (FR/NL/DE/EN/ES), generated by `build.mjs`, deployed to Cloudflare Pages.
No dependencies — everything is Node builtins, so there is nothing to `npm install`.

## Commands

```bash
npm test              # node --test test/*.mjs      — 24 tests, ~4s
npm run build         # PROD=1 node build.mjs       — the ONLY build whose output may be committed
npm run build:preview # node build.mjs              — noindexed local preview; NEVER commit its output
```

**`node --test test/` crashes** with `MODULE_NOT_FOUND` on Node 20+ — it resolves `test` as a
module, not a directory. The glob is required. Use `npm test` and this cannot bite you.

## The one way to break this site

A build without `PROD=1` stamps `<meta name="robots" content="noindex, nofollow">` on all 45 pages
and rewrites `robots.txt` to `Disallow: /`. **The generated output is committed to the repo** (54
tracked `index.html` files), so committing a preview build silently deindexes the live site.

`npm test` guards this — `the committed robots.txt is a production build, not a preview` fails if
you try. Run it before every commit that touches generated output.

The same trap exists at deploy time and the tests **cannot** see it: if the Cloudflare Pages project
is configured with a build command of `node build.mjs`, it regenerates every page without `PROD=1`
at deploy. The correct Pages setting is **no build command at all** — `wrangler.toml` sets
`pages_build_output_dir = "."`, so Pages should just serve the committed output.

## Editing content

**Never hand-edit `*/index.html`, `sitemap.xml`, `robots.txt` or the root `index.html`.** They are
generated and your change will be overwritten by the next build. Edit instead:

- `content/{fr,en,nl,de,es}.mjs` — all copy, plus each page's `render()` function.
- `build.mjs` — layout, shared header/footer, the translated-slug map, the page loop, sitemap.
- `styles.css`, `script.js` — hand-written, not generated.

Then run `npm run build` and commit both the source and the regenerated output.

`_redirects` and `.htaccess` are **static** and not regenerated — update them by hand if page slugs
change. `_redirects` is the one Cloudflare uses; `.htaccess` is Apache-only and kept for reference.

Facts — prices, the coach bio, schedules — come from `BRIEF.md`, not from the built pages.

## Before you say it works

Run `npm test`. The suite covers the things that are expensive to get wrong: noindex/robots
correctness, that every redirect target resolves to a real page, that the booking pages stay out of
production, that referenced images all exist and none exceeds 600 KB, and that no unreferenced
images ship. Green is meaningful here — do not claim a change is done without it.

Deploy state, owner-asset provenance and the redirect rationale live in memory (`~/brain/coco/`),
not in this file.
